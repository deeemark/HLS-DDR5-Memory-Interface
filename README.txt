DDR5 Memory Interface and Testbench
=======================================================

Baseline DDR5-3200 logical memory interface with two independently controlled
x32 subchannels. Each x32 subchannel comprises two x16 PHY lanes and an x32
behavioral DRAM model. The host uses 27-bit transaction addresses; bit 26
selects the subchannel and bits 25:0 are decoded locally.

Configuration:
DDR5-3200 logical CK = 1600 MHz (625 ps period); BL16; modeled RL26, WL24.
Each host transaction is 16 beats x 32 bits = 512 bits (64 bytes).
The mask is 64 bits, one per byte.

                              request FIFO, and timing enforcement

ddr5_write_phy_output_mux.cpp /.h : Write-data/strobe output multiplexing
ddr5_x32_write_phy.cpp /.h : Two x16 write PHY lanes for one x32 subchannel

ddr5_read_phy.h            : Top-level x16 read PHY integration
ddr5_read_phy_pos.cpp /.h  : Positive-edge portion of the read PHY
ddr5_read_phy_neg.cpp /.h  : Negative-edge portion of the read PHY
ddr5_x32_read_phy.cpp /.h : Two x16 read PHY lanes for one x32 subchannel

ddr5_x32_integrated.h      : One x32 controller/write PHY/read PHY subsystem
ddr5_dual_x32_router.h     : Host request routing and response collection
ddr5_dual_x32_integrated.h : Dual independent x32 subchannel top-level

Simulation and S2CBench files
-----------------------------
ddr5_x32_memory_model.cpp /.h : Behavioral DDR5 x32 memory model
main.cpp                      : Top-level test simulation and optional VCD
tb_ddr5_s2c.cpp /.h           : S2CBench-style testbench and comparisons
ddr_in_data.txt               : Input commands (four records, no header)
ddr_output_golden.txt         : Expected returned data
Makefile / Makefile.GNU        : SystemC simulation and CWB synthesis

Generated by simulation (not included as source files):
ddr_output.txt                : Observed READ responses
ddrdiff.txt                   : Per-response comparison report
trace_behav.vcd               : VCD trace produced by make wave

Input format: op subchannel local_addr_decimal seed_decimal mask_hex
  op: 1=WRITE, 0=READ
  subchannel: 0 or 1
  local address: 26-bit logical burst address, decimal
  seed: deterministic 512-bit data pattern generator parameter for writes
  mask: 64-bit hexadecimal byte-mask (0 means all bytes written)

Data pattern for 32-bit beat i (i=0..15):
  word[i] = (seed<<24) XOR (i*0x01010101) XOR 0x5A3210E7
The READ seed field is ignored by DRAM; read data comes from the model's
previously written backing store. The golden file stores the subchannel number
and full 512-bit hexadecimal data returned by each READ, one response per line.
Comparison is subchannel-aware and order-independent.

Default test:
  1) WRITE to SC0 and SC1 using different banks/rows and patterns.
  2) READ from both addresses.
  3) Check both data responses against the golden file.
  4) Require overlapping SC0/SC1 write-data activity.

Build and run:
  make clean
  make

Expected ending:
  Finished simulation SUCCESSFULLY

Waveforms:
  make wave

Generated VCD:
  trace_behav.vcd
Only post-initialization clock toggles are traced to avoid an extremely large
power-up waveform. Other signals are traced directly.

CWB 6.1 BDL synthesis:
  make synth

Clean build outputs:
  make clean

Environment:
The included Makefiles use the laboratory CyberWorkBench 6.1 and SystemC
2.3.0-ASI installation paths under /proj/cad/cwb-6.1. Compile options preserve
-std=gnu++98 and -D_GLIBCXX_USE_CXX11_ABI=0. This package does not include
RTL generation/simulation, specialized regressions, or scheduler benchmarks.
